# RAG-ассистент: чат-бот с поиском по внутренней документации

Streamlit-приложение из четырёх блоков:

1. **💬 Чат-бот** — полноценный ассистент с историей диалога в рамках сессии:
   - три режима: 📚 **по документации (RAG)**, 🧠 **рассуждения LLM**, 💬 **свободный чат**;
   - **классификатор** в RAG-режиме сам решает, относится ли вопрос к базе
     (служебные вопросы — по шаблонам, остальные — по уверенности ретривера:
     косинус ближайшего чанка против порога), и сообщает пользователю,
     будет ли поиск по внутренней документации;
   - подсказки-продолжения диалога (кнопки под последним ответом);
   - ответы RAG-режима — со ссылками на фрагменты [1], [2] и источниками;
   - всплывающая инструкция из трёх шагов при первом входе (кнопка «❓»).
2. **📥 Индексация** — один большой Markdown-файл → чанкер (заголовки,
   абзацы, код-блоки, перекрытие) → BGE-эмбеддинги (L2) → FAISS → `storage/`.
3. **🔍 Поиск** — «чистый» пайплайн косинусного top-k для демонстрации без чата.
4. **Генерация** (внутри чата и поиска) — GigaChat API с порогом релевантности.

## Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env       # вписать GIGACHAT_CREDENTIALS (без него поиск работает, генерация — нет)
streamlit run app.py
```

1. Вкладка **«📥 Индексация»**: загрузите `.md` (например, готовый
   `data/project_corpus.md`), при желании подстройте чанкинг, нажмите кнопку.
2. Вкладка **«🔍 Поиск»**: введите запрос → «Искать» → «🤖 Сгенерировать ответ».

## Модель эмбеддингов

По умолчанию **`deepvk/USER-bge-m3`** — дистилляция BAAI/bge-m3 специально
для русского языка от VK (359M параметров, ~1.4 ГБ, dim 768): качество
мультиязычной BGE при вдвое меньшем размере. Меняется одной строкой в `.env`.

Альтернативы: `BAAI/bge-m3` (568M, оригинал), `BAAI/bge-small-en-v1.5`
(33M, только английский).

Порог релевантности откалиброван на этой модели: осмысленные запросы дают
косинус 0.55–0.70, нерелевантные — 0.29–0.31, поэтому `RELEVANCE_THRESHOLD=0.50`
надёжно разделяет их. После смены модели проверьте порог через
`python scripts/test_gigachat.py`.

## Корпус

`data/project_corpus.md` — демо-корпус на 360 обращений (7 тем × 10 регионов)
плюс справочник «как подать обращение» с процедурными фактами (59-ФЗ, ЖКХ,
дороги, медицина, выплаты, экология) — на нём хорошо показывать ответы RAG.

Корпус собирается **шаблонным генератором без единого LLM-вызова**:

```bash
python scripts/make_corpus.py            # 360 обращений, seed 42
python scripts/make_corpus.py 500 --seed 7
```

Свой корпус — любой Markdown с заголовками-секциями по 500–1500 символов;
структура «заголовок = самодостаточный раздел» даёт лучший поиск.

## Конфигурация (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `EMBEDDING_MODEL` | `deepvk/USER-bge-m3` | модель SentenceTransformer |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `1000` / `200` | чанкинг, символов |
| `BATCH_SIZE` | `32` | батч эмбеддингов |
| `GIGACHAT_CREDENTIALS` | — | Authorization-ключ GigaChat (нужен для генерации) |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` | область доступа ключа |
| `GIGACHAT_MODEL` | `GigaChat-2` | модель генерации (доступные покажет `test_gigachat.py`) |
| `RELEVANCE_THRESHOLD` | `0.50` | косинус ниже порога = чанк нерелевантен, LLM не вызывается |
| `GENERATION_CONTEXT_HITS` | `5` | сколько чанков уходит в промпт |

## Архитектура

```
sample.md ─► (1) Индексация: чанкер → BGE (L2) → faiss.IndexFlatIP ─► storage/
запрос ────► (2) Поиск: BGE (L2) → IP = косинус → top-k чанков
              (3) Генерация: чанки ≥ порога + вопрос → GigaChat → ответ [1][2]
```

IP по L2-нормализованным векторам математически равен косинусу; `IndexFlatIP` —
точный перебор, для прототипных корпусов быстрее и честнее ANN.

**Косинус в цифрах** (USER-bge-m3, проектный корпус): «куда жаловаться на УК»
→ 0.67 у секции справочника; «рецепт борща» → 0.31 максимум. Порог 0.50.

## Структура проекта

```
app.py                    # Streamlit UI: Индексация / Поиск (+ генерация)
config.py                 # конфигурация (.env переопределяет)
pipelines/
  chunking.py             # чанкер: заголовки, абзацы, код-блоки, overlap
  indexing.py             # индексация → FAISS → атомарная запись в storage/
  search.py               # поиск: косинус top-k
  router.py               # классификатор «нужен ли RAG для этого вопроса»
  chat.py                 # чат-ассистент: 3 режима, история, подсказки
  generation.py           # GigaChat: промпт с контекстом, порог, ссылки [n]
data/
  project_corpus.md       # демо-корпус (генерируется make_corpus.py)
storage/                  # index.faiss + chunks.json + corpus.md + meta.json
scripts/
  make_corpus.py          # генератор корпуса (без LLM)
  smoke_test.py           # end-to-end без UI: индексация + поиск
  test_chunking.py        # юнит-тесты чанкера
  test_gigachat.py        # живая проверка GigaChat + калибровка порога
```

## Тесты

```bash
python scripts/test_chunking.py                        # чанкер, без модели
python scripts/smoke_test.py [файл.md] [запрос]        # индексация + поиск
python scripts/test_gigachat.py                        # GigaChat + порог + RAG-ответ
```

## Устранение типичных проблем

- **Первый запуск долго грузит модель** — BGE качается с HuggingFace
  (~1.4 ГБ для USER-bge-m3) в кэш `~/.cache/huggingface`.
- **«No such model» от GigaChat** — устаревшее имя модели; посмотрите список
  доступных (`test_gigachat.py` печатает его) и поправьте `GIGACHAT_MODEL`.
- **SSL/прокси ошибки при вызове GigaChat** — системный прокси/VPN режет
  сберовские хосты; приложение само добавляет их в `NO_PROXY` (см. `config.py`).
- **Сменили `EMBEDDING_MODEL` — поиск заблокирован** — индекс построен другой
  моделью; переиндексируйте на вкладке «Индексация».
- **Ответ «в базе нет данных» на адекватный вопрос** — снизьте
  `RELEVANCE_THRESHOLD` или проверьте, что корпус вообще покрывает тему.
